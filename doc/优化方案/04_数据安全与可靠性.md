# 04 数据安全与可靠性

> 状态：设计方案，未实现  
> 基线：e4b6af7  
> 当前事实 = 静态代码证据；指标 = 拟定验收目标

## 核心原则

1. **自动保存不丢数据** — 崩溃/断电后最多丢失 2 秒输入
2. **原子写防损坏** — 任何写入操作不可产生半截文件
3. **危险操作可撤销** — 删除/覆盖/恢复均有回退路径
4. **Agent 不可自动破坏笔记** — AI 仅建议，写入需用户确认

## §1 自动保存不丢数据

### 1.1 当前机制

```
用户输入 → Editor onUpdate → handleContentChange (App.tsx L1064)
  → updateActiveTab({content, isDirty: true})
  → debounce 2000ms → handleSaveRef.current()
    → writeFile(filePath, content)        // 直接 fs::write
    → create_backup(notePath, content)    // 仅主窗格
    → updateActiveTab({isDirty: false})
```

**缺陷**：
- debounce 期间崩溃 → 2 秒输入丢失（可接受，但无 WAL 兜底）
- `writeFile` 失败 → 前端不处理，`isDirty` 仍被设为 false（L836）
- 分屏 `handleSaveSplit` 不调用 `create_backup`
- 无保存队列，并发写入可能交叉

### 1.2 改进方案

```
┌─ 保存状态机 ─────────────────────────────────────────┐
│                                                       │
│  idle → dirty → saving → saved                       │
│                  ↓                                    │
│                error → retry(3次) → wal_fallback     │
│                                                       │
└───────────────────────────────────────────────────────┘
```

| 层级 | 机制 | 说明 |
|------|------|------|
| L1 内存 | debounce 2s | 当前已有 |
| L2 WAL | 每次 onChange 写入 localStorage WAL | 崩溃后恢复 |
| L3 磁盘 | 原子写（temp + rename） | 防损坏 |
| L4 备份 | 自动保存也触发 create_backup（≥5min 间隔） | 版本历史 |

**WAL 实现**：
```typescript
// hooks/useAutoSave.ts
const WAL_KEY = 'zennote-wal';

function writeWAL(filePath: string, content: string) {
  const wal = JSON.parse(localStorage.getItem(WAL_KEY) || '{}');
  wal[filePath] = { content, ts: Date.now() };
  localStorage.setItem(WAL_KEY, JSON.stringify(wal));
}

function recoverWAL(): Record<string, {content: string, ts: number}> {
  const wal = JSON.parse(localStorage.getItem(WAL_KEY) || '{}');
  localStorage.removeItem(WAL_KEY); // 恢复后清空
  return wal;
}
```

启动时检查 WAL → 若有未落盘内容 → 提示用户恢复。

### 1.3 保存失败处理

```typescript
// 改进后的 handleSave
const result = await writeFile(filePath, content);
if (!result.success) {
  // 不更新 isDirty，保持脏状态
  setSaveState('error');
  showToast(`保存失败: ${result.error}，内容已暂存`);
  writeWAL(filePath, content); // WAL 兜底
  return; // 不执行后续 backup/mtime 更新
}
```

## §2 原子写防损坏

### 2.1 当前写入（危险）

```rust
// commands.rs L550-553
fs::write(&path, &content)  // 直接覆盖目标文件
```

崩溃时机分析：
- `fs::write` 内部 = open(truncate) + write + close
- truncate 后崩溃 → 文件 0 字节 → **数据全丢**
- write 中途崩溃 → 文件截断 → **部分丢失**

### 2.2 原子写实现

```rust
// 规划新增: src-tauri/src/atomic_write.rs
use std::fs;
use std::io::Write;
use std::path::Path;

pub fn atomic_write(target: &Path, content: &[u8]) -> Result<(), String> {
    let dir = target.parent().ok_or("无父目录")?;
    let tmp = dir.join(format!(".{}.tmp", target.file_name()
        .ok_or("无文件名")?.to_string_lossy()));
    
    // 1. 写入临时文件
    let mut file = fs::File::create(&tmp)
        .map_err(|e| format!("创建临时文件失败: {}", e))?;
    file.write_all(content)
        .map_err(|e| format!("写入临时文件失败: {}", e))?;
    
    // 2. fsync 确保落盘
    file.sync_all()
        .map_err(|e| format!("sync 失败: {}", e))?;
    
    // 3. 原子 rename（POSIX 保证）
    fs::rename(&tmp, target)
        .map_err(|e| format!("rename 失败: {}", e))?;
    
    // 4. fsync 目录（确保 rename 落盘）
    if let Ok(dir_file) = fs::File::open(dir) {
        let _ = dir_file.sync_all();
    }
    
    Ok(())
}
```

**替换点**：
- `write_file` (L550)
- `write_text_file` (L473)
- `save_note` (L191)
- `create_backup` (L950)
- `export_note` (L277)

### 2.3 Windows 兼容

Windows 上 `rename` 不能覆盖已存在文件。需使用 `MoveFileEx` + `MOVEFILE_REPLACE_EXISTING`，或先 rename 目标为 `.bak` 再 rename tmp 为目标。

## §3 本地数据隐私与加密

### 3.1 当前状态

| 数据 | 存储位置 | 保护 |
|------|----------|------|
| 笔记内容 | 用户选择的目录 (.md) | 无加密（明文） |
| AI API Key | localStorage | 无加密 |
| 应用配置 | localStorage | 无加密 |
| 备份 | ~/.z-note/backups/ | 无加密 |
| 最近文件 | localStorage | 无加密 |

### 3.2 建议

| 优先级 | 措施 |
|--------|------|
| P1 | API Key 迁移到 Rust 侧 `~/.z-note/credentials.json`，文件权限 600 |
| P2 | 可选笔记本加密（AES-256-GCM），密码存 keychain |
| P2 | 备份目录权限收紧（700） |
| P1 | 导出时脱敏（移除 frontmatter 中的 api_key/token 等字段） |

**注意**：笔记本身为明文 .md 是产品特性（用户拥有数据、Git 友好），不应强制加密。加密为可选功能。

## §4 附件路径安全

### 4.1 当前风险

- `save_image` (commands.rs L374-407)：`note_id` 参数直接拼接文件名，无校验
  - 若 `note_id` 含 `../`，可写入任意目录
  - 实际调用方 `Editor.tsx` L383 使用 `currentFilePath.split('/').pop()?.replace('.md','')` — 通常安全，但无后端防护

- `read_image` (commands.rs L411-428)：`path` 参数直接 join `notes_dir()`
  - 若 path 含 `../`，可读取 notes_dir 外的文件

### 4.2 修复

```rust
fn sanitize_filename(name: &str) -> String {
    name.chars()
        .filter(|c| c.is_alphanumeric() || *c == '-' || *c == '_')
        .take(64)
        .collect()
}

// save_image 中:
let safe_id = sanitize_filename(&note_id);

// read_image 中:
let full_path = notes_dir().join(&path);
if !full_path.starts_with(notes_dir()) {
    return Err("路径越界".to_string());
}
```

## §5 危险操作确认与可撤销

### 5.1 当前保护

| 操作 | 确认 | 可撤销 |
|------|------|--------|
| 关闭脏标签 | ✅ window.confirm | ❌ 内容丢失 |
| 删除文件（Sidebar） | ✅ confirm + move_to_trash | ✅ 废纸篓 |
| 恢复版本 | ✅ confirm | ❌ 当前版本未备份 |
| 永久删除（command） | ❌ 无确认 | ❌ 不可恢复 |
| AI 插入内容 | ⚠️ 用户点击"Insert" | ✅ Cmd+Z |
| 外部修改覆盖 | ✅ confirm | ❌ 本地修改丢失 |

### 5.2 改进

| 操作 | 改进 |
|------|------|
| 恢复版本 | 恢复前自动 `create_backup` 当前版本 |
| 关闭脏标签 | 先触发保存，保存失败才 confirm |
| 永久删除 | 从 invoke_handler 移除 `delete_file`，或加二次确认 |
| 外部修改 | 提供"保留本地"/"保留磁盘"/"合并"三选 |
| 批量操作 | 任何影响 > 1 文件的操作需 confirm + 进度 + 可取消 |

## §6 Agent 不可自动删除/覆盖笔记

### 6.1 当前 AI 能力边界

`AIPanel.tsx` 提供的操作：
- summarize → 返回文本，用户手动插入
- tags → 返回标签建议
- outline → 返回大纲文本
- suggest-links → 返回链接建议
- chat → 对话，用户点击"Insert"插入编辑器

**当前安全**：AI 不直接调用 `write_file` / `delete_file`。  
**风险点**：`handleInsertText` (App.tsx L529-533) 直接插入编辑器 → 触发 onChange → 自动保存 → 写入磁盘。

### 6.2 规则（设计约束）

```
┌─ Agent/AI 操作分级 ─────────────────────────────────┐
│                                                      │
│  Level 0 (只读): 摘要、分析、标签建议               │
│    → 无需确认，不修改任何数据                       │
│                                                      │
│  Level 1 (建议): 生成内容、推荐链接                 │
│    → 展示预览，用户点击"插入"才写入编辑器           │
│                                                      │
│  Level 2 (写入): 修改笔记内容、添加标签             │
│    → 必须展示 diff 预览 + 用户显式确认              │
│    → 写入前自动创建备份                             │
│                                                      │
│  Level 3 (禁止): 删除笔记、覆盖文件、修改配置       │
│    → Agent 永远不可执行                             │
│    → 即使用户在对话中要求，也拒绝并提示手动操作     │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 6.3 实现约束

- `ai_chat` command 仅返回文本，不执行文件操作
- 前端 AI 相关代码禁止调用 `write_file` / `delete_file` / `rename_file`
- 未来若增加 Agent 工具调用（function calling），白名单限制为：`read_file`、`search_notes`、`list_dir`
- 黑名单（永不开放）：`delete_file`、`write_file`（直接）、`rename_file`、`move_to_trash`

## §7 Tauri 权限收敛

### 7.1 当前 capabilities

```json
// capabilities/default.json
"permissions": ["core:default", "clipboard-manager:default", "dialog:default", "fs:default", "shell:default"]
```

**问题**：
- `fs:default` 允许前端直接调用 Tauri FS API（绕过 Rust commands 的 validate_path）
- `shell:default` 允许打开外部程序（潜在风险）
- 自定义 commands 的 `validate_path` 允许整个 home 目录

### 7.2 收敛方案

```json
{
  "permissions": [
    "core:default",
    "clipboard-manager:default",
    "dialog:default",
    {
      "identifier": "fs:allow-read-file",
      "allow": [{ "path": "$HOME/.z-note/**" }, { "path": "$DOCUMENT/**" }]
    },
    "shell:allow-open"
  ]
}
```

- 移除 `fs:default`（前端不直接使用 Tauri FS API，全部走自定义 commands）
- `shell` 仅保留 `allow-open`（打开 Finder/浏览器）
- 自定义 commands 的 `validate_path` 收窄为：当前打开的笔记目录 + `~/.z-note/` + `/tmp/zennote-export/`

### 7.3 CSP 收紧

```json
"security": {
  "csp": "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' asset: data: blob:; font-src 'self' data:; connect-src 'self' ipc: http://localhost:*"
}
```

- 移除 `unsafe-eval`（Tiptap/Mermaid 不需要）
- 移除 `unsafe-inline`（script）— 需验证 Vite 构建产物
- `connect-src` 限制为 self + ipc + localhost（AI 请求走 Rust 代理，不需前端直连）
- 移除 `https:`（AI 请求已由 `ai_chat` command 在 Rust 侧发出）

## §8 导出内容脱敏

### 8.1 风险

导出 HTML/PDF 时，内容可能包含：
- 文件绝对路径（`/Users/xxx/...`）
- API Key（若用户误粘贴到笔记中）
- 内部链接（`[[私密笔记]]`）

### 8.2 脱敏规则

| 模式 | 处理 |
|------|------|
| `/Users/[^/]+/` | 替换为 `/Users/***/` |
| `sk-[a-zA-Z0-9]{20,}` | 替换为 `sk-***REDACTED***` |
| `Bearer [a-zA-Z0-9._-]+` | 替换为 `Bearer ***` |
| frontmatter 中 `api_key`/`token`/`password` 字段 | 移除 |

导出时提供选项："脱敏导出"（默认开）/ "原始导出"。

## §9 备份与恢复可靠性

### 9.1 当前备份机制

```rust
// commands.rs L938-964
create_backup(note_path, content)
  → ~/.z-note/backups/{path_with_underscores}/{timestamp}.md
  → 保留最近 20 个，超出删除最旧
```

**问题**：
- 备份目录名用 `_` 替换 `/`，不同路径可能冲突（`/a/b.md` 和 `/a_b.md`）
- 无完整性校验（备份文件本身可能被损坏）
- 20 个上限对高频编辑者不够（每天 50 次保存 → 不到半天就轮转完）

### 9.2 改进

| 项目 | 方案 |
|------|------|
| 目录命名 | 使用路径的 SHA256 前 16 位 + 可读后缀 |
| 完整性 | 备份文件头部写入 `<!-- checksum:sha256:xxx -->` |
| 保留策略 | 最近 20 个 + 每天最早 1 个保留 30 天 + 每周最早 1 个保留 90 天 |
| 存储空间 | 显示备份占用空间，提供清理入口 |
| 恢复安全 | 恢复前自动备份当前版本 |
