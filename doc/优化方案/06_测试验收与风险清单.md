## 三、测试夹具规范

### 3.1 隔离原则

```
所有测试使用临时目录，绝不碰真实用户笔记：
- Rust: tempfile::tempdir() → /tmp/zennote-test-xxxxx/
- 前端: vitest mock + jsdom，不涉及真实文件系统
- E2E: 专用测试笔记库 fixture（git 管理，< 50 文件）
- 性能: 生成脚本创建 N 篇随机笔记到 tempdir
```

### 3.2 夹具生成

```rust
// tests/fixtures.rs
pub fn create_test_vault(dir: &Path, count: usize) {
    for i in 0..count {
        let content = format!("# Note {}\n\nContent with #tag{} and [[Note {}]]\n", i, i%5, i+1);
        fs::write(dir.join(format!("note_{:04}.md", i)), &content).unwrap();
    }
}
```

## 五、验收流程

```
开发完成 → 自测（单元+集成）→ PR → CI 门禁（typecheck+test+clippy）
  → Code Review → 合并 → 手动 E2E 验证 → Release
```

**门禁规则**：
- CI 全绿才可合并
- P0 任务必须有对应故障注入测试
- 性能指标回退 > 10% 阻塞合并
- 安全测试（路径遍历/XSS/CSP）为必选项
