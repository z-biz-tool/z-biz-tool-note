## 2. 顺带修掉的 2 个真缺陷（台账没记）

### 2.1 原子写并发写同一个文件 ⇒ 临时名撞车 ⇒ 内容被截断

原实现：临时文件名只带 pid。

```rust
// 改前
let tmp = dir.join(format!(".{}.{}.tmp", file_name, std::process::id()));
```

同一进程里两次写**同一个**文件（例如自动保存与手动保存撞在一起）会共用同一个临时文件 ——
后一次的 `File::create` 把前一次已写好的内容**截断**，
前一次 rename 走掉的是**后一次**的内容，后一次再 rename 则报 ENOENT。
结果是「落盘内容与调用方预期不符」＋「后一次保存被当成失败」。

改法：加进程内自增序号（`static TMP_COUNTER: AtomicU64`），
每次调用独占一个临时文件。配套新增测试 `bulk_writes_dont_collide`、
`temp_path_is_unique_per_call`、`concurrent_writes_to_same_target_all_succeed`。

**这是数据损坏类缺陷**（存进去的不是你以为的那份内容），优先级高于台账里多数条目。

### 2.2 原子写失败时不清理临时文件 ⇒ 用户笔记目录里留垃圾

原实现：`File::create` / `write_all` / `sync_all` 任一步失败就直接 `?` 返回，
临时文件留在原地 —— 而它就落在**用户的笔记目录里**，
是个既不是笔记、又被文件树/搜索忽略的**用户看不见也删不掉的垃圾文件**。

改法：三步失败各自显式清理临时文件再返回错误。
配套新增测试 `failed_rename_cleans_up_temp_file`、`no_tmp_files_left_behind`。
